# Canon: terminologi

## Syfte

Denna fil håller bokens centrala begrepp konsekventa. Begreppen ska användas likadant i manus, kapitelplan, metadata och exempel.

## Centrala begrepp

| Begrepp | Rekommenderad användning | Kort definition |
|---|---|---|
| Bild | Används om fristående visualisering utan underliggande modellstruktur. | En ritad representation som främst kommunicerar i stunden. |
| Modell | Används om strukturerad representation med element och relationer. | En återanvändbar beskrivning av något i arkitekturen. |
| Vy | Används om ett målgruppsanpassat utsnitt ur en modell. | En presentation av delar av modellen för en viss fråga eller målgrupp. |
| Modellfråga | Används om frågan modellen ska hjälpa till att besvara. | Den styr vilka delar av modellen som behövs. |
| Modellnytta | Används om den praktiska effekt modellen ger. | Bättre förståelse, spårbarhet, analys, prioritering eller beslut. |
| Minsta användbara modell | Används som princip för avgränsning. | Den minsta modell som räcker för att ge nytta i en viss situation. |
| Förmåga | Används för vad verksamheten behöver kunna göra. | Stabil beskrivning av verksamhetens kapacitet. |
| Verksamhetsprocess | Används för arbete eller flöde som utförs. | En sekvens eller struktur av aktiviteter i verksamheten. |
| Verksamhetstjänst | Används för vad verksamheten erbjuder en mottagare. | Ett värde som tillhandahålls till intern eller extern part. |
| Applikationskomponent | Används för en avgränsad applikation eller systemdel. | En programvarudel med ansvar i applikationslandskapet. |
| Applikationstjänst | Används för vad en applikation erbjuder. | Funktionellt stöd som verksamhet eller andra applikationer använder. |
| Informationsobjekt | Används för information som verksamheten behöver förstå och hantera. | Ett begreppsligt informationsinnehåll, till exempel importdeklaration. |
| Tekniklager | Används bara när teknik påverkar beslut, risk eller genomförbarhet. | Modellering av plattformar, noder, nätverk och tekniska beroenden. |
| Drivkraft | Används för yttre eller inre kraft som motiverar förändring. | Exempelvis ökade handelsvolymer eller nya regelkrav. |
| Mål | Används för önskat resultat. | Ett tillstånd organisationen vill uppnå. |
| Krav | Används för villkor eller förmåga som arkitekturen måste uppfylla. | Något lösningen eller verksamheten behöver stödja. |
| Princip | Används för styrande arkitekturregel. | En riktlinje som påverkar design- och prioriteringsval. |
| Arbetspaket | Används för avgränsat förändringsarbete. | Ett initiativ, projekt eller arbetsområde som levererar förändring. |
| Leverans | Används för resultat från ett arbetspaket. | En konkret förändring eller förmåga som införs. |
| Platå | Används för ett arkitekturtillstånd vid en tidpunkt. | Nuläge, mellanläge eller målarkitektur. |
| Gap | Används för skillnad mellan två platåer. | Det som behöver förändras mellan nuläge och målbild. |
| Relation | Används för semantiskt samband mellan element. | Där modellens analysvärde uppstår. |
| Bortval | Används positivt, inte som brist. | Ett medvetet beslut att inte modellera något just nu. |

## Språkprincip

Boken är på svenska. Vedertagna engelska begrepp får användas när svenska termer riskerar att bli otydliga, till exempel viewpoint, governance eller capability om sammanhanget kräver det. Första gången ett sådant begrepp används bör svensk förklaring ges.
